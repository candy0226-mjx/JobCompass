# JobCompass 故障排查

最后核对：2026-10-13。按“现象 → 检查 → 处理”持续补充；命令默认在项目根目录运行，不把数据清空当成启动修复。

## 1. Docker 命令找不到

Docker Desktop 已安装，也可能只是终端 PATH 没更新。先重新打开终端。Windows 每用户安装可检查：

```powershell
$dockerExe = Join-Path $env:LOCALAPPDATA 'Programs\DockerDesktop\resources\bin\docker.exe'
if (Test-Path -LiteralPath $dockerExe) {
    & $dockerExe version
}
```

另一种常见安装目录为 `C:\Program Files\Docker\Docker\resources\bin`。以本机实际文件为准；找到后用完整路径调用，或将所在目录加入 PATH。

完整路径方式启动本项目基础服务：

```powershell
& $dockerExe compose -f deploy/docker-compose.yml -f deploy/docker-compose.local.yml up -d postgres redis minio
```

## 2. Docker 提示找不到 Linux engine 管道

通常表示 Desktop 引擎尚未启动或启动失败，不能仅凭这个错误断定镜像不存在。先打开 Docker Desktop，等待运行就绪，再执行 `docker version`。

项目当前使用 Linux 镜像。若出现虚拟化/WSL 报错，分别检查 BIOS 虚拟化、Windows 相关功能和 WSL 状态；有错误弹窗时保留完整错误，再按实际问题处理。

`sailor-ingest.sock` 曾在本机启动故障中出现。不能仅凭旧截图断定所有版本都有同一 Bug，也不把恢复出厂设置作为默认步骤；退出 Desktop 后排查残留进程及对应运行文件，版本问题应核实官方发布说明。

## 3. 后端连接不上 PostgreSQL

```powershell
Test-NetConnection localhost -Port 5432
docker compose -f deploy/docker-compose.yml -f deploy/docker-compose.local.yml ps
docker compose -f deploy/docker-compose.yml -f deploy/docker-compose.local.yml logs --tail 60 postgres
```

检查数据库容器、5432 映射、根 `.env` 的实际连接及凭据。Docker 中的数据库仍可由 IDEA/数据库工具通过 `localhost:5432` 访问，无需另装 Windows PostgreSQL。

如果密码认证失败，核对实际库内账号；已有数据卷不会因修改 Compose 环境变量就自动修改旧账号密码。日志分享前隐藏私人信息。

## 4. Flyway、vector 扩展或向量维度错误

先确认镜像为项目配置的 `pgvector/pgvector:pg17`，查看扩展和迁移状态：

```powershell
docker exec resume-ai-postgres psql -U resume_ai -d resume_ai -c 'SELECT extname, extversion FROM pg_extension;'
docker exec resume-ai-postgres psql -U resume_ai -d resume_ai -c 'SELECT version, description, success FROM flyway_schema_history ORDER BY installed_rank;'
```

以上使用默认开发账号；账号已改动时相应调整。空库首次初始化前可能没有 Flyway 表。

扩展不可用时解决镜像/权限；校验和不一致时查迁移历史与实际改动，不随意修改已执行脚本。当前维度为 1024，向量模型输出应一致。切换维度必须评估迁移和重新索引，不能只改变量。

## 5. 前端打开了，数据加载失败

```powershell
Invoke-RestMethod 'http://localhost:8080/actuator/health'
```

后端未启动时，前端页面可以打开但请求失败。确认 `NEXT_PUBLIC_API_BASE_URL` 为浏览器能够访问的地址，本机默认 `http://localhost:8080/api/v1`。数据库健康、后端可访问、模型能调用需要分别检查。

`/api/v1/status` 主要展示配置/组件信息，不能单凭显示 `CONFIGURED` 认定真实模型调用成功。生产前端修改 API 地址后需重新构建。

## 6. 8080 或 3000 端口被占用

```powershell
Get-NetTCPConnection -State Listen | Where-Object { $_.LocalPort -in 8080,3000 } | Select-Object LocalPort,OwningProcess
```

核对 PID 对应的进程，停止自己之前启动的服务，再换启动方式。不要按端口批量结束未知进程。

## 7. AI 分析失败、队列满或重启中断

| 错误码或状态 | 含义 | 处理 |
|---|---|---|
| `MODEL_FAILED` / `ANALYSIS_FAILED` | 模型阶段或其他分析环节失败 | 检查 Key、地址、模型工具调用能力及服务可用性，修正后重试 |
| `INVALID_EVIDENCE` | 输出结构或引用不符合校验规则 | 检查输出/提示词；失败结果不会伪装成成功报告 |
| `QUEUE_FULL`，HTTP 429 | 本机 2 个执行线程、8 个等待名额已满 | 等待任务结束再重试，失败运行 ID 保留 |
| `FAILED / INTERRUPTED` | 重启发现尚未完成的旧任务 | 手动重试；当前没有自动恢复执行队列 |

新运行的重试绑定旧运行的简历版本与岗位快照。修改根 `.env` 后重启后端；不要将模型 Key 发到日志或聊天里。

## 8. 复核、计划或任务提示冲突

HTTP 409 通常是版本或状态冲突。刷新数据，确认最新版本，再提交操作；不要通过强行移除版本检查解决。

草稿先保存再确认。确认后内容固定，任务进度只能更新已选中的任务。相同幂等键的重复确认会复用结果；不同计划复用同一键会冲突。

## 9. PDF 解析失败或记录无法删除

新 PDF 入口限 5MB、10 页，不支持加密或扫描 OCR。扫描简历改为粘贴正文。上传失败先看错误提示，不用反复上传同一不可解析文件。

新版本快照的简历和被分析/申请引用的岗位受删除保护，目的是保留报告依据。当前没有归档/解除引用管理入口，不直接在数据库删关联记录绕过保护。

## 10. 知识库没检索到新内容

文档保存后还需索引，修改后需重新索引。检查向量服务 Key、模型维度和索引状态。聊天成功不代表向量模型可用；文本检索兜底也不代表向量索引成功。
