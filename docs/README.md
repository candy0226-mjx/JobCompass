## 怎样持续维护

使用“已实现 / 待开发 / 待验证 / 暂缓”标记功能状态。“过去验收通过”与“服务现在正在运行”是两个事实，记录时分别说明。

| 改动类型 | 同步更新 |
|---|---|
| 页面、用户操作或输入限制 | `USER_GUIDE.md` |
| 接口、请求字段、错误或状态 | `api-design.md` |
| 模型、数据来源、配置 | `DATA_PROVIDER.md`、示例配置；依赖变化再更新 `tech-stack.md` |
| 模块、事务、任务执行或检索设计 | `architecture.md` |
| 新需求、实施步骤、延期 | `实施计划.md`；`roadmap.md` 只保留方向摘要 |
| 修复、验证结论、测试样例 | `验收记录.md`；可复用排查方法写入 `故障排查.md` |
| 简历或面试表述 | `面试问答.md`，只描述有代码或验证依据的能力 |

可在相关文档末尾添加以下记录，也可以直接调整原章节。无需为每次改动生成一个新文件。

```text
日期：YYYY-MM-DD
改动：
状态：已实现 / 待开发 / 待验证 / 暂缓
对应代码或配置：
验证方法与结果：
尚未解决的问题：
```

## 从参考项目借鉴了什么

参考：本机 `E:\githubProject\ai-customer-service-agent-master`。借鉴文档组织和开发辅助方式，内容依据 JobCompass 当前代码重新编写。

| 参考项目的辅助信息 | JobCompass 的处理 |
|---|---|
| `USER_GUIDE.md`：按用户操作组织手册 | 补全本项目启动、操作、输入边界和预期结果 |
| `DATA_PROVIDER.md`：把接入方式讲清楚 | 说明已有 REST 接口、模型配置和未来接入边界；当前没有可插拔 `DATA_PROVIDER` 开关 |
| `实施计划.md`：步骤与验证对应 | 改为可调整的需求清单、实施模板和验收条件 |
| `面试问答.md`：按主题准备追问 | 增加源码入口、实现范围和真实验证依据 |
| `CONTRIBUTING.md`：环境、提交流程与问题报告 | 采用 Java/Next.js 的现有命令，提供问题报告与变更说明模板 |
| 启动脚本、Compose、`.env.example` | 继续使用现有脚本与配置，说明本机与容器的地址区别 |
| Dockerfile、云部署配置 | 可作为后续部署思路；本项目目前仅用 Compose 启动基础服务，全应用容器部署待开发 |

参考中的固定用户路径、固定等待秒数和浏览器使用容器内部域名的方式不适合直接照搬。后续完善脚本时优先探测运行环境和健康状态；浏览器请求的 API 地址必须从浏览器所在电脑可访问。

目前没有新增 CI、CLI、认证系统或动态数据 Provider。这些都可按实际需要加入实施计划，完成后再更新状态。
