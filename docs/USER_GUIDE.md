# 求职罗盘用户使用手册

最后核对：2026-10-13。页面和操作变化后直接更新本文件。

## 1. 这个系统怎么用

放入简历和感兴趣的岗位 → 查看匹配依据 → 确认自己的真实情况 → 按可投入时间制定准备计划 → 更新任务与投递进度 → 用新版简历重新分析。

例如：你想投三个 Java 实习岗位，每周能准备 8 小时。系统分别分析三个岗位，把能够合并的准备事项放在一起，保留它们各自对应的岗位，再给出时间预算内的安排。你确认后执行任务；投递由你自行完成，在系统中记录进度。

首次体验可使用 `samples/resumes/` 和 `samples/jobs/` 中的已有示例正文。它们需要通过页面或接口录入，不会自动进入数据库；专门的模型评估样例另放在 `samples/jobcompass-evaluation.json`。

## 2. 启动前准备

| 组件 | 当前用途 |
|---|---|
| JDK 21、Maven 3.9+ | 在 IDEA 或命令行运行后端 |
| Node.js 20.9+，满足当前 Next.js 16 要求 | 运行前端；具体版本以当前依赖要求为准 |
| Docker Desktop，使用 Linux 容器 | 启动 PostgreSQL 17 + pgvector、Redis、Silo 文件存储 |
| 聊天模型 Key、向量模型 Key | DeepSeek 用于分析；百炼向量模型用于原项目知识库索引与检索 |

使用当前 Docker 配置时，不需要在 Windows 上另外安装 PostgreSQL。数据库仍在你的电脑上运行，只是运行在容器里。

所有命令默认在项目根目录运行，本机为 `E:\agentProject\JobCompass`。

### 配置文件

根目录 `.env` 已存在时直接编辑原文件，不覆盖已有 Key。首次配置才执行：

```powershell
if (-not (Test-Path -LiteralPath '.env')) {
    Copy-Item -LiteralPath '.env.example' -Destination '.env'
}
```

数据库、文件存储、聊天和向量配置见 [数据与模型接入指南](DATA_PROVIDER.md)。不要把真实 Key 填入公开示例。

### 第一步：启动基础服务

先打开 Docker Desktop，等待引擎就绪，然后执行：

```powershell
docker compose -f deploy/docker-compose.yml -f deploy/docker-compose.local.yml up -d postgres redis minio
docker compose -f deploy/docker-compose.yml -f deploy/docker-compose.local.yml ps
```

`minio` 是服务名；本地覆盖文件实际使用兼容 MinIO API 的 Silo。只启动以上三个服务即可，云端模型方式无需启动 Ollama。

如果 `docker` 命令找不到，先按 [故障排查](故障排查.md) 确认安装路径。数据库容器应显示运行，健康检查最终为 `healthy`。

### 第二步：启动后端

IDEA：导入 `backend/pom.xml`，选择 JDK 21，运行仓库的 `JobCompass Backend` 配置；模块名不匹配时选择实际 Maven 模块。也可以运行 `com.resumeai.ResumeAiAgentApplication`，工作目录设为 `backend`，自动读取 `../.env`。

命令行方式，在一个终端运行：

```powershell
.\scripts\start-backend.ps1
```

Flyway 自动初始化数据库表和扩展。IDEA 与命令行任选一种启动方式，8080 已被自己的旧后端占用时先停止那个进程。

### 第三步：启动前端

在另一个终端运行：

```powershell
.\scripts\start-frontend.ps1
```

首次缺少依赖时脚本会安装依赖；之后复用现有目录。打开 `http://localhost:3000/compass`。

检查后端：

```powershell
Invoke-RestMethod 'http://localhost:8080/actuator/health'
```

返回 `UP` 是本次服务健康检查；历史验收记录不代表现在服务仍在运行。

## 3. 完整操作流程

### 放入简历与岗位

在“求职罗盘”工作台创建文本简历、上传 PDF，或选择已有简历并固定版本。新 PDF 入口限 5MB、10 页，需要可提取文字；扫描版可改为粘贴正文。简历正文与 JD 正文各不超过 20,000 字符。

录入公司、岗位名称、招聘要求，可补充地点、来源链接和截止日期。来源链接用于记录，不会自动抓取网页。

选择最多三个岗位开始分析。每个岗位分别生成运行记录，分析过程中可以在报告页查看进度；失败时查看提示并手动重试。

### 看报告、确认真实情况

| 页面判断 | 通俗含义 |
|---|---|
| 有证据 `MATCH` | 简历里有能够支持该要求的经历 |
| 明确缺口 `GAP` | 有明确不满足条件的原文依据 |
| 证据不足 `UNCERTAIN` | 暂时判断不了；没写不等于不会 |

查看岗位引用、简历引用和理由，再按真实情况选择“已核实，无需准备 / 完善经历表述 / 完成实践任务 / 核实情况”。补充备注；如需合并技能，可选择系统支持的技能键。

复核单独保存，原模型报告保留。不要为了提高匹配结果补写不存在的经历。

### 用追问补充没写清楚的经历

在成功报告的某条要求下点击“追问并整理经历”。AI 根据固定简历、岗位要求和原判断，提出业务场景、实际实现与职责、验证与结果三个问题。

如实填写回答，可以留空，或直接说明“没有做过、不记得、未验证”。每项最多 2000 字符。先保存回答，再生成证据卡草稿，核对完整原文并勾选真实性确认后保存。

证据卡由 Java 按三个角度组织回答，不交给模型改写事实。每段标为用户补充；“已确认”表示用户认可其真实，不代表系统已经独立核验，也不改变原报告的判断。空白回答不补全。

确认后可以复制或下载 Markdown；需要修正时“重新编辑回答”，上一张确认卡保留在历史记录中。补入简历需要自行创建新版正文，再重新分析。

每条要求复用同一追问记录。模型生成失败可重试；资料仍是原报告的版本和岗位快照。追问线程为本机有界队列，重启中断时保留失败状态。修改回答前端要求先保存，版本冲突时刷新已保存内容后再操作。

### 生成并调整计划

回到工作台，选择同一简历版本、不同岗位的 1–3 份成功报告，填写每周预算和岗位重要程度。

系统把相同技能、相同准备类型的事项合并，再安排预算内能容纳的任务；未知技能默认保持独立。未安排的任务仍可查看。

草稿里可以修改任务标题、可检查产物、预计耗时、是否选择和预算。耗时是估计值，需要你确认，不代表保证在该时间内掌握技能。

保存草稿后确认。确认后内容固定，可以更新进度；如需重新规划，另建草稿。

### 执行准备、记录投递

选中的任务可按“待准备 → 准备中 → 已完成”更新，也支持跳过及回退修正。确认计划时，为来源岗位建立或复用投递记录，不重置已有状态。

在 `/applications` 中手动更新“计划投递、已投递、面试中、收到 Offer、未通过、已撤回”，补充渠道、日期等备注。系统不会代你向招聘网站投递。

完成任务后可以创建新版简历再分析。勾选完成不会自动把旧报告改成“匹配”。

## 4. 原有简历优化与知识库

原仓库的上传、匹配评分、改写、导出和知识库页面保留。新求职罗盘流程与旧评分流程分别使用各自的报告。

原流程操作：在“简历定制”上传文件、填写目标岗位，生成分析后进入改写草稿。查看原文/改写差异、理由和校验说明；需要调整时点击“对话重写”，输入具体要求，先预览候选，再接受或拒绝。接受时保存该候选对应的正文、理由和校验信息，刷新后仍可查看；生成候选本身不会覆盖已应用的正文。

重新生成会记录对话与生成次数，只允许确认最新的待处理候选。若提示候选过期，或使用修复前生成且尚未确认的旧候选，请重新生成再确认。拒绝候选不会替换已应用的正文。

确认后点击“导出 Markdown”或“导出 PDF”，再点击出现的下载链接。文件存放在 Silo（MinIO 兼容 API），临时链接有效期为一小时；过期后重新导出。当前导出是优化段落及岗位、理由、校验信息，并非完整简历排版模板。

事实校验说明由模型生成，即使显示“无需人工复核”，仍应逐项核对真实经历、数字及未完成事项；它不是独立事实核验。模型失败时原模块有保留/回退行为，不能仅凭出现草稿就认定真实模型调用成功。

知识文档保存后需要点击索引，才写入向量库。修改后重新索引；向量检索异常或没有结果时，旧检索服务会尝试文本搜索，但索引仍需可用的向量模型。

新证据分析直接读取简历/JD 快照，并未接入知识库召回。知识库更适合提供写作或岗位准备建议，不能作为用户具备某项能力的证据。

## 5. 日常停止与数据保存

在运行前后端的终端按 `Ctrl+C`，或使用 IDEA 停止按钮。停止基础服务：

```powershell
docker compose -f deploy/docker-compose.yml -f deploy/docker-compose.local.yml stop postgres redis minio
```

再次使用时执行原来的 `up -d` 命令。数据库和文件使用 Docker 数据卷保存；停止容器不会删除数据卷。需要备份或清理数据时，先确认具体对象及备份，不将删除数据卷作为常规停止步骤。

## 6. 当前范围与后续补充

当前为本机单用户项目，没有多用户数据隔离、招聘网站自动抓取、自动投递或计划归档入口。有新版本快照的简历、已有分析/申请引用的岗位受删除保护。原改写与导出链路已于 2026-10-14 用虚构 TXT、真实模型及单页 PDF 完成主流程回归；其他输入格式与多页复杂排版没有在这次重新验证。详细范围见 [验收记录](验收记录.md)。

后续操作变化直接修改对应步骤，新增问题写入 [故障排查](故障排查.md)，新增验收写入 [验收记录](验收记录.md)。
