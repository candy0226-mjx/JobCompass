## 可复现的检查

命令、数据库凭据读取方式及真实模型额度影响见 [贡献指南](../CONTRIBUTING.md)。以下场景可用来验收业务行为：

| 场景 | 操作 | 预期 |
|---|---|---|
| 版本固定 | 使用旧版生成报告，再创建新版 | 旧报告仍对应旧文本与岗位快照 |
| 无依据判断 | 简历只提 Redis 名称，JD 要求一致性设计 | 不因关键词相同直接认定具备该设计经历 |
| 缺少记录 | 简历没有 Redis 内容 | 缺少记录本身不作为明确能力缺口 |
| 引用伪造 | 测试输出包含不存在的段落 ID 或改写引文 | 后端校验拒绝；不保存成成功报告 |
| 范围混用 | 尝试混合不同简历版本/同一岗位报告生成计划 | 拒绝不合法组合 |
| 任务合并 | 同版本三个岗位包含同技能、同类型任务 | 合并并保留三个岗位来源；不同技能/任务类型不误合并 |
| 预算不足 | 草稿选中耗时超过预算 | 前后端阻止保存；数据不部分写入 |
| 重复确认 | 对同一计划重复提交相同幂等键 | 不重复创建申请，不重置已有状态 |
| 并发覆盖 | 用旧版本号再次更新 | 返回冲突，刷新后重新操作 |
| 中途失败 | 数据库集成测试注入事件写入失败 | 确认事务回滚，计划与申请不留下半完成结果 |
| 进程中断 | 重启后有遗留运行 | 标为 `FAILED / INTERRUPTED`，用户可手动重试 |
| 计划执行 | 更新选中任务和投递状态 | 保存进度与事件，旧证据报告不被自动改写 |
